# Public Roadmap

> **Build what earns proof. Improve what earns reuse. Productize what earns demand.**

This roadmap is intentionally short. It exists to make the project's current bets visible without turning every idea into a promise.

## NOW — prove first use

- [x] Publish `v0.1.0-alpha.1`.
- [x] Ship a dependency-free two-minute proof demo.
- [x] Add a complete human usage field manual.
- [x] Open real `good first issue` contribution paths.
- [ ] Reach the first **10 real external users**.
- [x] Publish the first signed `ai-workbench-mcp` prerelease to PyPI through Trusted Publishing and verify an exact-version clean install.
- [x] Publish the verified package metadata to the official MCP Registry only after `server.json` passes the current publisher validator.
- [x] Record one maintainer-run real-host verification for all three public MCP tools.
- [ ] Collect one independent real-host verification for the standalone MCP package.
- [ ] Collect independent runtime verification for at least two Agent Skills hosts.
- [ ] Add at least two external or independently reproduced end-to-end workflow examples.
- [ ] Identify the top three repeated friction points from real use.

## NEXT — improve the winning path

Only start these after the NOW evidence exists:

- simplify the most common first-use friction;
- deepen the workflow people choose most often;
- add examples around repeated real questions;
- improve cross-runtime installation evidence;
- prepare the next prerelease from observed fixes and reuse.

## LATER — validate a paid companion

Only enter this lane when the growth/productization gates show a real buyer signal:

- implementation/customization pilot;
- productized recurring creator-ops service;
- maintained automation pack;
- Pinterest Growth OS;
- Reels Production OS;
- Canva + AI Content Factory;
- AI Creator OS / managed workflow layer.

## NOT NOW

- adding Agent Skills just to increase the count;
- building a hosted SaaS before repeat use;
- paywalling useful open-core workflows;
- auto-publishing to external platforms without proven approval/failure behavior;
- vanity dashboards with no decision attached;
- fake `Used by` claims, fake testimonials or inflated adoption numbers.

## How priorities change

A roadmap item can move when evidence changes.

Strong signals include:

1. repeated independent use;
2. the same friction reported by multiple users;
3. external contributions;
4. direct requests for a deeper/managed outcome;
5. a paid pilot or explicit buyer commitment.

Stars are useful discovery evidence, but they do not override stronger usage evidence.

## Contribute to the roadmap

Do not open a feature request that says only “add X.”

Include:

- the real job you are trying to complete;
- what you tried;
- where the current workflow stopped helping;
- what a successful result would look like.
