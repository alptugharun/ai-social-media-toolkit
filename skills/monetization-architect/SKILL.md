# Monetization Architect

Design a commercial layer around a useful open-source project.

Do not start with pricing.

Start with demonstrated value.

## Required Reference

Read:

- `references/OPEN-SOURCE-MONETIZATION-PLAYBOOK.md`
- `references/EVIDENCE-POLICY.md`

## Input

Identify:

- project
- target user
- current adoption evidence
- free value
- recurring job
- maintenance cost
- data / API cost
- support burden
- strongest differentiator
- current distribution surface

## Step 1 — Choose the first monetization layer

Use this priority unless evidence suggests otherwise:

1. implementation / service
2. paid recurring report
3. hosted convenience
4. premium companion asset
5. sponsor support
6. Marketplace distribution
7. enterprise plan

Why:

Services and reports can validate willingness to pay before building a large SaaS platform.

## Step 2 — Keep the open core useful

Define:

### Free

What remains genuinely useful and inspectable.

### Paid

What adds convenience, scale, history, support, collaboration or specialized delivery.

Do not make the public repository intentionally frustrating.

## Step 3 — Define a proof contract

Examples:

- saves X manual steps
- produces a reusable client report
- reduces research time
- gives multi-client history
- creates a repeatable local-market brief
- creates a usable creator-location plan

Do not insert invented numbers.

The proof contract should define what to measure in a real test.

## Step 4 — Price as a hypothesis

Allowed outputs:

- pricing structure options
- value metric
- billing interval
- free / paid boundary
- trial concept

Label all prices as hypotheses until validated with real buyers.

## Step 5 — Distribution

Possible surfaces:

- GitHub README
- GitHub Releases
- GitHub Marketplace
- GitHub Sponsors
- alptugharun.com
- LinkedIn
- ADYA Creative
- product demo
- case study
- workshop

## Step 6 — Automation

Automate:

- opportunity monitoring
- report generation
- issue creation
- product metrics collection when available
- draft release notes
- draft sales collateral
- draft client report

Keep human approval for:

- outreach
- pricing changes
- billing
- contracts
- sponsorship acceptance
- public claims
- data exports
