# First 10 Real Users — Launch Operating Plan

The next milestone is **not 100 stars**. It is ten independent people who can run or use one public workflow and tell us what happened.

## Definition of a real user

Count someone only when at least one of these is visible or directly evidenced:

- they install one Agent Skill;
- they run the two-minute demo;
- they use one Creator Material on a real task;
- they open a genuine question/bug/feedback issue;
- they fork the repository to adapt a workflow;
- they contribute a focused pull request.

A like, impression or passive page view is not a real-user event.

## Launch asset

Lead with one proof, not the whole catalog:

**“I built an open-source creator-operations toolkit. You can verify two decisions in two minutes without an API key.”**

Primary path:

`visitor → two-minute demo → one relevant workflow → feedback issue → return for release/update`

## Cohort

Recruit the first ten from audiences already adjacent to the problem:

- social-media managers;
- AI-assisted creators;
- Pinterest creators;
- short-form/Reels creators;
- small agencies;
- Agent Skills / Claude Code / Codex / Cursor users interested in marketing workflows.

Do not mass-DM strangers. Prefer public posts, existing professional relationships, opt-in communities and people who already engage with creator/AI workflow content.

## What to ask

One request only:

> Run the two-minute demo or one workflow. Tell me the first place you got confused, blocked, or wanted a deeper version.

Do not ask for a star before value is experienced.

## Success gate

After ten real users, review:

- first-result completion rate;
- repeated friction points;
- workflows people choose without prompting;
- repeat use;
- external issues/forks/contributions;
- direct requests for a deeper or managed version.

## Stop / change condition

If people understand the README but do not run anything, improve the demo/distribution.

If they run the demo but do not continue to a workflow, improve the next-step routing.

If they use a workflow but do not return, improve repeated value before adding features.

If several independent users ask for the same deeper outcome, send that evidence through the productization gates.
